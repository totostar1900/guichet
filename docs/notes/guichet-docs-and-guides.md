Documentation lives **in the app, not in static docs** (user's decision 2026-09-18: "pages in the app with filter and research, a guide on each side, like Claude's docs"). One Claude doc remains from that day (the platforms/costs recap, superseded by the in-app page but kept as a shareable link); the half-filled "Comment fonctionne Guichet" doc was deleted at the user's request.

- Content: `src/data/docs/*.ts` (`fonctionnement`, `plateformes`, `support`, `administration`, `technique`, `aide`), every text as `l(fr, en)`; blocks p/lead/list/steps/table/flow/note/link; rendered by `src/components/docs/DocBlocks.tsx`. Each page has `checkedOn` + `owner` ("vérifié le" shown in the outline).
- Desk side `/desk/docs` (Pilotage › Documentation): index with chapter search + audience chips; `/desk/docs/[slug]` = nav tree · page · "Sur cette page" outline (scroll-spy, `Outline.tsx`).
- **Audience rule** (user insisted): `visibility: "desk" | "public"`. Only `public` pages render to clients, on `/info/aide`; a public page must be `audience: ["client"]` and `src/test/docs.test.ts` fails the build if it contains internal words (/desk, Supabase, Vercel, Resend, keys, SQL, webhook, cron, SVT, fraud, repo paths, project id). Today the only public page is `aide`; its last chapter « Comment Guichet est entretenu » is the client-facing maintenance note (user chose this over exposing the notes page to clients, 2026-09-18). Audience chips are labels, not permissions : the route is the permission.
- Working notes: `docs/notes/*.md` (copies of these memory files) are rendered on `/desk/docs/notes` (src/lib/notes.ts + src/components/docs/Markdown.tsx, files traced via next.config `outputFileTracingIncludes`). Keep the repo copy in sync when a memory file changes.
- Desk guide `/desk/guide`: `src/data/desk-guide.ts` (GUIDE sections; a section may carry `shots: [{key, caption}]` gallery; TOUR stops may carry `link` and `image`). Screenshots: `npm run guide:shots` against `npm run dev:memory` → `public/guide/*.png`; the script forces `guichet_lang=fr`, and entries accept `{width, height, prep, settle, then}` (prep runs before a `setTimeout(reload)`, then settle, then `then`). Tour step count is computed (`TOUR.length`), never hard-coded.
- Client tours: `CoachMarks` walk-throughs on the fiche (`id="fiche"`, 5 stops incl. « Chaque chiffre s'explique »), `/actualites` (`actualites`), `/info` (`info`, 4 stops), `/info/aide` (`aide`, 4 stops ending on the maintenance chapter); onboarding `Onboarding.tsx` has six screens, screen 5 shows real phone captures `onboarding-info.png` + `onboarding-aide.png`.
- The desk tour cannot leave `/desk`: client pages enter it as stops with a `link` (+ preview image) on the desk page that feeds them (Référentiel → Info; Documentation → Aide). Desk tour = 20 stops; the last one is the notes page. Guide galleries: Documentation (index + 6 pages + aide client + aide-entretien + info client + premiers-pas + docs-notes), Référentiel (info-client, aide-client, aide-entretien). Shots script supports `maxHeight` per entry (Aide pages captured at up to 4200 px so the last chapter shows) and `then` to prune sections before a focused capture. Never add internal pages (notes, technique…) to a client tour : refused once, user agreed.

Guide shots regenerated 2026-09-19 night (43 shots, nine of them phone-width; GROUP/ONLY filters in scripts/guide-shots.mjs; see [[guichet-phone-ux]]).

**Why:** a fintech's docs must sit where people work and carry a review date; clients must never reach internal procedures. **How to apply:** a screen change ⇒ update its doc page text + `checkedOn`, its guide section, regenerate shots, and keep new client-facing pages `visibility: "public"` only after the sensitivity test passes. See [[guichet-project]].

**2026-09-20, the Guide on the phone.** `src/app/info/GuideBar.tsx` is mounted on every Guide page (info, lesson, parcours, aide, mentions): phone-only navy bar with the sommaire sheet (search over `/api/guide-index`, both courses with done counts from `readDoneLessons`, tools) + prev/next; `BackToTop lift` keeps the chevron above it. The Aide page is `AideBrowser` (client): search in place, chips for `TOP_QUESTIONS`, tiles per chapter, answers as `#q-<slug>` (slug = `slugOf(question.fr)` in `src/lib/guide-index.ts`), "utile ? oui/non" → `helpFeedback` logs to the journal. The ⋮ menu has three tabs (Aide with the same search, Contact, Réglages) and reads the index through `src/lib/guide-index-client.ts` (client-safe types in `guide-index-shared.ts`; the builder is server-only). Financial profile: `src/data/profile.ts` (questions FR/EN, `computeProfile`, `profileFlag`), page `/moi/profil`, migration 0028 (`financial_profile` jsonb, `intents.profile_flag`).

**2026-09-20, the double button.** `GuideBar.tsx` no longer draws a band: it is a fixed capsule bottom-right (phone only, `.corner`). From a lesson the page passes `chapter={key, letter, color, title}` + `lessonKey` (first course: letter = the lesson number, gold): the capsule is `.double` (pastille with the `Ring` + sommaire), both open the same `Sheet` with `tall` (fixed 620px on the phone) and `tabs` (labels are ReactNodes: the small ring / the lines icon), `foot` = Précédente / Suivante. Tab « Ce chapitre » = « Vous êtes ici » block + the chapter's lessons (ticks from `readDoneLessons`); tab « Tout le Guide » = the former sommaire. Horizontal swipe in the body switches tabs; a scroll listener sets `.folded` for 900 ms after each downward scroll (sommaire half collapses, badge on the pastille). Without `chapter` the capsule is the sommaire alone and the sheet shows a « Vous êtes ici · {pos.label} » line, no tabs. The index is loaded on mount so the ring is right at rest. ActorsMap (`src/components/lessons/Diagrams.tsx`) renders `MapSvg` for the desk and a `.stack` of three bands on the phone, plus `MapZoom` (portal, pointer events: one finger pans, two pinch, double tap fit ↔ 2×; portrait shows the « Tournez le téléphone » line).
